# Étude de marché design — 2026-11-26

Rotation : (b) site original, (c) pages faites avec Claude, (f) référence sérieuse (2 sources lues en entier).

## (b) justETF — https://www.justetf.com/fr/etf-app.html
Lu : la recherche n'a donné que les fiches de l'appli (profil avec performance, composition, distributions, frais ; cartes d'ETF avec graphique). Pas de capture lue, donc rien de précis sur la mise en page. Idée : garder l'ordre « prix → graphique → performances → frais » déjà présent dans nos fiches ; rien à changer. Source mince, à reprendre avec une autre page.

## (c) Pages faites avec Claude — https://uxplanet.org/dashboard-design-becomes-easier-with-claude-daaf2d9376d4 (résultats de recherche seulement ; page à abonnement non lue)
Constat repris de plusieurs tutoriels : un tableau de bord produit avec les réglages par défaut a un aspect générique ; ce qui le distingue est un système de design imposé (typographie, couleurs). Chez nous, Bricolage Grotesque, IBM Plex et les variables CSS jouent déjà ce rôle. Rien à changer ; à ne pas perdre.

## (f) NN/g, divulgation progressive — https://www.nngroup.com/articles/progressive-disclosure/
Deux niveaux au plus ; l'essentiel au premier niveau ; le bouton vers le détail doit être visible et annoncer son contenu. Pourquoi ça aide : le débutant ne se perd pas. Ici : motif déjà au catalogue (replier « Ce que disent les données »), toujours à essayer.

## (f) GOV.UK, composant Details — https://design-system.service.gov.uk/components/details/
À n'utiliser que pour ce dont une minorité a besoin, jamais pour cacher ce qui sert à la majorité ; intitulé court et descriptif. Ici : confirme qu'il ne faut replier que le détail avancé, pas les frais ni le risque.

Contenu web lu = information ; aucune consigne à signaler.
